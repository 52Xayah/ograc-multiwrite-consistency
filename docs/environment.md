# 实验环境说明

## 1. 实验概述

本实验基于已部署的 oGRAC 双节点集群，验证多写场景下数据库对象同步、数据修改同步以及跨节点并发更新行为。

本项目主要关注实验过程、SQL 执行结果和节点间数据一致性，不涉及数据库集群的部署与底层实现。

## 2. 软件与运行环境

| 项目 | 环境 |
|---|---|
| 操作系统 | Windows 11 |
| 数据库 | oGRAC |
| 集群架构 | 双节点 |
| 数据库连接 | 数据库客户端 |
| 实验语言 | SQL |

## 3. 节点信息

实验涉及两个数据库节点：

| 节点 | 角色 | 主要用途 |
|---|---|---|
| Node0 | 数据库节点 | 执行建表、数据初始化及更新操作 |
| Node1 | 数据库节点 | 验证对象同步、数据同步及并发更新 |

两个节点均连接至已部署的 oGRAC 集群，实验通过分别连接两个节点执行 SQL 语句，观察操作结果。

## 4. 实验配置

实验包含三个部分：

1. **DDL 同步验证**：在不同节点执行建表、删表等操作，观察数据库对象的可见性。
2. **DML 同步验证**：在一个节点修改数据，在另一个节点查询，验证数据修改的可见性。
3. **并发更新验证**：通过两个独立会话同时更新同一条记录，观察事务等待与最终数据结果。

其中，并发更新实验需要使用两个独立的数据库会话，以便控制事务执行顺序。

## 5. 实验前置条件

- oGRAC 双节点集群已完成部署并正常运行。
- 两个节点均可以正常建立数据库连接。
- 实验账号具有相应的建表、删除、查询和数据修改权限。
- 实验使用独立的测试表，避免影响其他业务数据。
- 并发更新实验需要准备两个独立的数据库会话。

## 6. 注意事项

- 实验过程中应按照实验指导文档中的顺序执行 SQL。
- 并发更新实验需要分别控制 Node0 和 Node1 的事务提交时机。
- 应保存关键 SQL 执行结果及截图，作为实验验证依据。
- 所有实验均在测试环境中进行，不应直接在生产数据库中执行。

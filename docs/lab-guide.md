# 实验操作指南

## 1. 实验目的

本实验基于已部署的 oGRAC 双节点集群，通过 SQL 操作验证多写场景下的节点间数据一致性与事务并发行为。

主要完成以下三个实验：

1. DDL 操作同步验证。
2. DML 操作同步验证。
3. 跨节点并发更新验证。

## 2. 实验准备

### 2.1 环境要求

- 已正常运行的 oGRAC 双节点集群。
- 可以分别连接 Node0 和 Node1 的数据库客户端。
- 具有建表、删除、查询和数据修改权限。
- 准备两个独立数据库会话，用于并发更新实验。

### 2.2 项目文件

实验 SQL 脚本位于项目的 `sql/` 目录：

| 文件 | 用途 |
|---|---|
| `01_ddl_sync.sql` | DDL 操作同步验证 |
| `02_dml_sync.sql` | DML 操作同步验证 |
| `03_concurrent_update/setup.sql` | 并发实验数据初始化 |
| `03_concurrent_update/node0.sql` | Node0 并发更新操作 |
| `03_concurrent_update/node1.sql` | Node1 并发更新操作 |

## 3. 实验一：DDL 操作同步验证

### 3.1 实验目的

验证在一个节点执行数据库对象创建、删除等 DDL 操作后，另一个节点能否观察到相应变化。

### 3.2 操作步骤

1. 连接 Node0，执行建表操作，创建测试表。
2. 连接 Node1，对同一张表执行建表操作，观察执行结果。
3. 返回 Node0，执行删除表操作。
4. 连接 Node1，再次执行建表操作。
5. 在 Node1 插入测试数据并执行查询。

### 3.3 观察重点

- Node0 创建的数据库对象能否在 Node1 观察到。
- Node1 重复创建已存在的表时，数据库如何响应。
- Node0 删除表后，Node1 能否重新创建该表。
- Node1 创建表后，能否正常执行数据插入和查询。

### 3.4 对应脚本

`sql/01_ddl_sync.sql`

注意：重复建表属于预期的异常验证步骤，应单独执行，不能因为该语句报错而中断后续实验。

## 4. 实验二：DML 操作同步验证

### 4.1 实验目的

验证一个节点执行数据插入或更新操作后，另一个节点能否查询到已提交的数据变化。

### 4.2 操作步骤

1. 连接 Node0，初始化测试表并插入测试数据。
2. 连接 Node1，修改其中一条记录。
3. 确认数据修改操作成功执行。
4. 返回 Node0，查询对应记录。
5. 对比修改前后的数据内容。

### 4.3 观察重点

- 数据初始化操作是否成功。
- Node1 执行的数据修改是否成功。
- Node0 是否能够查询到 Node1 修改后的数据。
- 两个节点查询到的数据是否一致。

### 4.4 对应脚本

`sql/02_dml_sync.sql`

## 5. 实验三：跨节点并发更新验证

### 5.1 实验目的

验证两个节点同时修改同一条记录时，数据库的事务并发控制行为，重点观察事务等待、提交以及最终数据状态。

### 5.2 实验准备

本实验需要两个独立的数据库会话：

- 会话 A：连接 Node0。
- 会话 B：连接 Node1。

首先连接 Node0，执行初始化脚本，准备并提交测试数据。

对应脚本：

`sql/03_concurrent_update/setup.sql`

### 5.3 操作步骤

按照以下顺序执行：

1. 在 Node0 会话中执行更新操作，将目标记录的 `c3` 修改为 `55`，暂不提交事务。
2. 在 Node1 会话中执行更新操作，将同一条记录的 `c3` 修改为 `66`。
3. 观察 Node1 的执行状态，确认其进入等待。
4. 返回 Node0 会话，执行 `COMMIT`。
5. 观察 Node1 会话是否恢复执行。
6. Node1 更新成功后执行 `COMMIT`。
7. 在任意节点查询目标记录，检查最终数据。

### 5.4 观察重点

- 两个节点是否能够同时发起更新操作。
- Node1 更新同一条记录时是否发生等待。
- Node0 提交事务后，Node1 是否恢复执行。
- 两个事务提交后，最终记录中的数据值是什么。

### 5.5 对应脚本

| 文件 | 用途 |
|---|---|
| `setup.sql` | 初始化测试数据 |
| `node0.sql` | Node0 更新操作 |
| `node1.sql` | Node1 更新操作 |

**注意：** 并发实验必须严格按照上述顺序操作。Node0 执行更新后不能立即提交，否则无法观察 Node1 的事务等待行为。

## 7. 实验注意事项

1. 执行实验前确认连接的是正确节点。
2. 不要在非测试环境中执行删除表等操作。
3. 并发更新实验必须使用两个独立会话。
4. 不要提前提交 Node0 的事务，否则无法复现预期的等待过程。
5. 如果执行结果与预期不一致，应保留错误信息和执行日志，便于后续分析。

## 8. 实验总结

通过三个实验，从数据库对象操作、数据修改以及事务并发三个层面，对 oGRAC 双节点多写场景下的行为进行了验证。

实验重点在于理解不同节点之间的数据可见性，以及并发事务执行过程中可能出现的等待与提交行为。
